# Spec Delta

## MODIFIED Requirements

### Requirement: 合并附属数据

冲突合并 SHALL 取编辑历史、引用、表情、消息合并关系、提醒与整理文档的并集；同一键冲突时取会话更新时间较新一侧，仍相同则按内容摘要确定性选择。提醒按标识合并，MUST 取 `updatedAt` 较新的状态，已取消或已触发的提醒 MUST 以该状态传播，避免在另一设备重复通知。

#### Scenario: 两端各加表情
- **WHEN** 两端对同一消息分别添加不同表情后同步
- **THEN** 合并后的对话同时保留两个表情

#### Scenario: 两端各设提醒
- **WHEN** 两端离线时分别为同一对话设置不同时间的提醒后重新同步
- **THEN** 合并后的对话同时保留两条待触发提醒

#### Scenario: 一端取消提醒
- **WHEN** 设备 A 取消了设备 B 上仍然待触发的同一条提醒，随后两端同步
- **THEN** 两端该提醒都变为已取消，且都不再发出通知

#### Scenario: 一端已触发提醒
- **WHEN** 设备 A 的提醒已触发，设备 B 上仍为待触发，随后两端同步
- **THEN** 合并结果保留较新的已触发状态，设备 B 不再为该提醒发出通知
