# Spec Delta

## Purpose

规定整理结果文档的阅读层级：对话名作为大标题、日期作为小标题，每条消息的时间并入正文开头，避免时间单独成行造成的多余标题层级。

## ADDED Requirements

### Requirement: 整理文档的标题与时间排版

整理文档 SHALL 使用两级标题：一级标题 `#` 为对话名，日期小标题 `##` 使用 `yyyy年M月d日` 并在跨天时按日期分段。每条消息 MUST 以 `『HH:mm』` 作为正文前缀并与正文处于同一段落，例如 `『09:00』正文内容`；MUST NOT 再输出单独的时间标题行或加粗时间行。消息正文中原有的 Markdown 格式 SHALL 保留，正文首行之外的后续行不重复添加时间前缀。

#### Scenario: 查看整理结果
- **WHEN** 用户打开已生成的整理结果页
- **THEN** 第一行是对话名大标题，随后是按天分段的小标题，每条消息以 `『09:00』正文` 的形式呈现，没有单独的时间行

#### Scenario: 跨天对话
- **WHEN** 整理内容跨越两个自然日
- **THEN** 文档按日期出现多个日期小标题，每条消息仍以所属时间的 `『HH:mm』` 开头

#### Scenario: 多行正文
- **WHEN** 一条消息正文包含多个段落
- **THEN** 只有正文首行带 `『HH:mm』` 前缀，后续段落保持原有内容与格式

#### Scenario: 本地与模型整理一致的结构
- **WHEN** 未配置模型使用本地整理，或配置模型使用 AI 整理
- **THEN** 两者都按对话名、日期小标题、`『HH:mm』` 正文的同一结构组织；AI 请求的系统提示词明确要求该结构

#### Scenario: 已保存的旧文档
- **WHEN** 用户查看本变更前已保存的整理文档
- **THEN** 文档内容保持原样，不自动迁移；重新整理后使用新结构
