# Design

## Context

动机见 proposal.md。已检查根目录、AGENTS.md、README.md、需求基线和 SVN 状态：已有 OpenSpec、SVN r2 与未纳管的需求文件；缺少 Android 工程、构建脚本、测试、数据库、导航、主题及 AI 实现，`bootstrap.md` 不存在。需求第 8 节所称“现有基础数据模型”只能作为逻辑建议，不能视为已有 Room 实体。

冲突：项目上下文仍称技术栈未确定，需求现已指定 Kotlin 原生路线；实施阶段更新该说明。需求中的 Git 指令按当前项目 SVN 约定执行。没有现存规范需要兼容或覆盖。

## Goals / Non-Goals

**Goals:** 使用单应用模块、明确的数据边界和可注入服务，按 Phase 0–4 逐步交付；核心正确性可以脱离真实模型验证。

**Non-Goals:** 不引入重型 DI、供应商 SDK、后端、跨平台框架；不要求先做完整模块化。语音图片入口仅禁用占位；不做自动后台持久任务调度。

## Decisions

### 1. 原生工程与交付边界

采用 Gradle Kotlin DSL、Kotlin、Compose、Material 3、Coroutines/Flow、Room、Retrofit/OkHttp 与 Kotlin Serialization，单 `app` 模块按 `ui/`、`data/`、`ai/` 分包，手动构造依赖。Compose → ViewModel → Repository，用户选定目录中的版本化文件为记录事实源，Room 是可重建查询缓存。相较重型分层和多模块，这适合从零开始的个人应用。

Phase 0 固定兼容的 Gradle/AGP/Kotlin/SDK 版本和 Wrapper，记录本地 JDK/SDK 前置条件；具体版本在实施时根据官方兼容表及本机环境核实，不在规划中猜测。建议 minSdk 26、英文包名 `com.chatnotebook.app`，作为可调整的工程默认值，不代表发布标识。每阶段完成构建、相关测试再推进；实施请求可限定到单阶段。

### 2. 数据与事务

记录文件采用 UTF-8 JSON 全量快照（schemaVersion、generation、createdAt、sessions、messages、editHistory、quotes、reactions、aiResults、mergeRelations 与内容校验值）；在用户通过 Storage Access Framework 选定的共享文档目录写入，不使用随卸载清理的应用专属目录。每次变更先创建新 generation 文档，完成写入并校验后才更新 Room 缓存，保留上一有效 generation；启动时扫描并载入最新校验通过的快照，损坏或未完成文件跳过并提示。重装后重新选择目录恢复，旧授权不视为仍有效。目录未授权或写入失败时操作失败并保留输入草稿，不展示为已保存；文件不含 API Key。此方案便于人工备份、格式迁移和故障恢复，代价是每次写入全量快照，首版适合个人记录规模，后续可改为增量格式而不改变外部契约。Room 初始 schema 从 v1 建立并导出，后续每次变更显式迁移、禁止 destructive fallback。时间使用 UTC epoch，显示转换本地时区；排序键为 createdAt 和稳定 ID。实体使用英文命名，UI 文案集中中文资源。

- ChatSession：id、title、createdAt、updatedAt、isDeleted、lastOpenedAt；标题修改和删除均经过记录快照事务。
- Message：id、sessionId、role、rawContent（不可变）、currentContent、contentVersion、createdAt、updatedAt、isDeleted、processingStatus；session 外键及 (sessionId, createdAt, id) 索引。
- MessageEditHistory：messageId、fromVersion、toVersion、oldContent、newContent、editedAt，版本唯一约束。
- AIProcessingResult：messageId、sourceContentVersion、requestId、providerConfigId（可空）、modelSnapshot、cleanedContent、summary、keywords、structuredData、processedAt、有效状态。不同请求可保留历史，只有当前版本最新请求可有效。
- MessageQuote：messageId、quotedMessageId、发送时文本快照；源消息删除时统一展示删除占位，不泄露旧快照；源编辑后显示发送时引用预览并允许查看源当前内容。
- MessageReaction：messageId、emoji，个人应用每条消息每种 Emoji 最多一项，计数为 1；可同时添加不同 Emoji，取消则删除对应项。
- MessageMergeRecord：当前对话内合并消息及有序来源消息 ID；原消息软删除但保留原文与编辑历史。已有 SessionMergeRecord/Source 仅用于兼容历史记录文件。
- LLMProviderConfig：非敏感设置、协议、文本能力、超时、凭据引用、时间；默认配置单独保存引用。

所有记录变更先在内存构造完整新快照，文件校验成功后刷新 Room；消息合并也以单份完整快照提交，避免半成品。编辑保存历史、递增版本并标旧结果过期；删除和批量删除同时令结果失效。引用外键不级联硬删除。UI 清理已删除选择项，编辑取消不落库。

### 3. AI 执行与并发

AIService 只负责组织文本，LLMProvider 提供 chat/testConnection；Repository 先保存消息，只有用户从历史对话长按菜单手动发起整理时才以应用级协程处理该对话，避免页面切换造成重复发送。每次请求捕获 messageId/version/requestId；响应入库事务检查未删除、版本一致且请求仍为最新，否则丢弃其当前结果资格。进程中止后将遗留处理中标记为可重试失败，不自动重发收费请求。此方案比第一版引入 WorkManager 和后台重试更可控。

结果 schema 定义 cleanedContent、summary、keywords、structuredData；structuredData 含 todos、times、people、places，允许无信息时空数组，不确定信息带显式标识。Kotlin Serialization 后执行类型、必填字段和合理长度校验，失败不生成有效结果。提示词要求中文、事实与推测分离，视用户内容为待整理数据。模型无法保证事实绝对正确，界面始终保留原文入口并标注 AI 派生结果。

Mock 通过显式模式或测试注入，不在真实请求失败时兜底。AI 整理结果仅在独立整理结果页按来源消息展示，避免把摘要混写回用户消息；聊天页不显示逐条整理卡片或处理状态。消息角色结构仍支持 AI 消息及其上下文操作。

### 4. Provider 与凭据

先实现通用可配置 OpenAI Compatible 文本适配器；DeepSeek、Qwen、Kimi、MiniMax、OpenAI 和自定义作为 Provider 类型，不复制六套相同请求实现。协议或特殊能力不兼容时明确报错，后续按真实接口证据增加独立适配器。Base URL 规范化为 API 根路径并集中构造 endpoint，避免重复路径。固定连接/读取超时，首版非流式文本，无自动付费重试；请求快照隔离模型切换。

Android Keystore 中持有 AES-GCM 加密密钥，随机 IV 加密 API Key，密文放应用私有凭据存储，Room 仅存引用。客户端只用 HTTPS，Base URL 不允许嵌入账号或查询凭据。凭据和 Room 缓存不参与系统云备份，防止不可解密恢复和非预期上传。记录用户 BYOK 的设备所有者可提取密钥这一边界，不承诺客户端绝对保密。

Room 与凭据存储无法共享事务：新增先写凭据再写配置，失败清理；更新使用新凭据引用后清理旧值；删除先停用、清默认，删除凭据成功再删除配置，失败保留可重试清理状态。启动时清理无引用凭据。网络日志禁止记录 Authorization、正文及完整错误体，错误统一映射中文脱敏分类。

### 5. Compose 交互

以聊天页为启动目的地；有记录时恢复上次 Session，无记录时展示空白聊天页。输入框初始未聚焦，不自动打开软键盘。顶部菜单按钮和屏幕左缘右滑均打开左侧 Drawer；顶部放齿轮设置入口与显著的新建对话操作，下方为带标题的历史会话列表。点击历史项切换；长按提供重命名和删除。删除采用 Session 软删除，连同其消息从正常查询中排除，文件快照保留可追溯历史，确认框说明关联消息将从正常列表移除；取消不写入。删除当前 Session 后转入最近可用 Session 或空白聊天页。左缘手势仅在抽屉关闭且不干扰消息纵向滚动时触发。未选定可写记录目录时保存或创建会话先引导选择。聊天页和设置页采用轻量导航。消息列表稳定 key、日期分组；点击显示时间状态不落库，新增自身消息滚动到可见位置，用户上翻时后台结果更新不强行拉到底部。输入状态经 ViewModel/SavedStateHandle 保留。菜单权限由角色决定，多选模式优先切换选中态，避免与单击时间冲突。删除统一确认，编辑和引用具有取消入口；批量复制按当前显示顺序以换行分隔。

输入栏参照 X 应用中 Grok 聊天页的圆角浅灰两层面板：上层独占宽度用于多行文字，下层左侧仅放附件图标，右侧空输入时显示语音按钮、输入文字后换为发送按钮；未实现的附件与语音保留禁用语义。输入栏固定在聊天内容底部，消息列表占据其上方剩余空间。聚焦弹出键盘时，以实际可见窗口和 IME Insets 计算底部位置，让输入栏容器紧邻键盘上沿；窗口采用不自动平移的输入模式，Scaffold 不再额外提供底部系统栏 padding，由 Compose 在同一内容容器消费导航栏和 IME Insets，避免重复偏移形成空白带。屏幕高度不足时暂收顶部栏与目录提示，并压缩输入面板内边距及文字行高；键盘收起后恢复顶部栏，目录入口保留在顶部栏。输入控件可保留自身内边距，但容器与键盘之间不另加间隔。键盘收起后恢复底部布局；竖屏、横屏、小屏以及手势和三键导航均检查输入栏完整可见、消息可滚动，启动时仍不主动聚焦。

发送只保存消息，不自动调用模型。左侧历史对话长按菜单增加“整理”和“查看整理结果”：选择“整理”立即对该 Session 的当前非删除消息启动一轮处理，短暂提示“后台整理中”，无确认步骤；同一 Session 已有运行中的整理时拒绝重复启动。处理由应用级作用域持有，切换聊天页不取消；若进程被系统终止，沿用已有中断恢复策略，标记失败且不自动重发付费请求。请求仍逐条绑定消息版本和请求标识，旧响应不得成为新版本的有效结果。整理页集中展示每条结果、模拟标识和失败重试；聊天页不显示整理结果、处理中、失败、过期或重试入口。手动启动时的短暂提示是唯一的聊天页整理反馈。

每轮整理完成并产生可查看结果时，为该 Session 持久化未读结果标记；左侧列表仅在该 Session 显示红点，点击红点进入整理结果页并将标记持久化为已读。点击标题仍切换对话；红点消失后可通过长按“查看整理结果”再次进入。未读标记作为记录元数据进入版本化文件，Room 仅作缓存，使应用重启或重装恢复后状态一致。结果页查看状态和新一轮完成状态按轮次比较，避免用户查看旧结果时清除随后完成的新红点；失败状态在整理页展示，不伪造完成红点。

### 6. 合并语义

用户长按当前对话中的消息选择“多选”，工具栏提供复制、删除和合并。选中至少两条后，先展示按消息时间及 ID 稳定排序的内容预览；确认后在同一份长期记录快照里创建一条用户消息，并软删除所选消息。新消息的原文为合并时的内容，时间取所选消息最早时间，故显示在原位置；相邻消息以单个换行分隔，不额外插入空白行，非用户来源加角色标记。原消息及编辑历史保留在文件中，通过 `MessageMergeRecord` 记录合并消息与来源消息的关系，普通聊天列表只显示新消息。原消息的 AI 结果在同一事务中过期，引用其内容的位置沿用“原消息已删除”占位。合并不自动调用模型。先写完整文件再刷新 Room；历史跨 Session 合并数据仍可读取，但界面不再提供跨对话合并入口。

## Risks / Trade-offs

- [外部供应商协议变化] → 测试使用固定协议 fixture；真实连接由用户配置核验，不声明所有模型已兼容。
- [长文本与上下文限制] → 先逐条整理，超限显示错误，禁止静默截断原文。
- [客户端凭据与个人信息] → 加密、HTTPS、最少日志、排除备份；明确设备失陷边界。
- [多存储凭据清理失败] → 可重试清理状态和孤立项清理，不隐藏失败。
- [合并大量消息事务较长] → IO 调度、禁重复提交、失败完整回滚；首版不引入跨事务分批半成品。
- [共享文档提供方不保证原子重命名] → 使用带代数与校验值的不可变快照文件，恢复时只接受完整有效版本，保留上一有效版本。
- [本机 Android 工具未检查] → Phase 0 验证 JDK/SDK/模拟器，缺失环境明确报告，不将未执行检查记作通过。

## Migration Plan

从空工程建立记录文件 schema v1 和 Room 缓存 schema v1，按阶段测试与 SVN 小提交；本次规划不提交用户需求文件或修改应用代码。将来的 Room 升级保留 schema、提供迁移测试；已有用户数据后不可用卸载或删库作为升级回退。发布前记录阶段验收、构建命令和设备验证结果。SVN 回退代码与数据库迁移分别处理，代码回退不代表数据库可降级。

## Open Questions

正式应用名称、图标、发布包名及签名策略留到发布准备时确认；不影响当前原型、数据契约和任务拆分。真实模型 ID 由用户配置，不需要在规划阶段选定。
