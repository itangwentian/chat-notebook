# Proposal

## Why

当前 Activity 没有统一拦截系统返回事件：在设置页或整理结果页按返回键/手势时，应用会直接结束并回到桌面，而不是回到上一级界面。用户预期的导航规则是“只有对话界面的返回才退出应用，其他界面的返回逐级回退”。

## What Changes

- 在对话界面（含会话抽屉关闭后的默认状态）按返回时，保持现有行为：结束应用并回到桌面。
- 在设置页按返回时回到对话界面；设置内部的模型配置表单、隐私政策与用户协议页面按返回时先回到设置列表。
- 在整理结果页按返回时回到对话界面。
- 系统返回键与返回手势使用同一套层级判断；对话框、底部面板与侧边抽屉沿用框架已有的返回关闭行为。
- 不改变任何界面的关闭按钮、退出确认或数据状态。

## Capabilities

### New Capabilities

- `app-navigation`: 定义应用级返回导航层级，明确对话界面退出应用、其余界面逐级回退的规则。

### Modified Capabilities

（无）

## Impact

- 代码：`MainActivity` 的根级界面切换、`SettingsScreen` 的页内层级、`OrganizationResultsScreen` 的返回入口。
- 测试：新增/补充返回导航的 Compose 测试。
- 无数据模型、持久化格式、同步协议或依赖变更。
