# Proposal

## Why

默认对话的创建条件目前是“记录目录完全没有任何文件”。用户首次安装时通常会选择“下载”或“文档”这类已有无关文件、空子目录的目录，此时默认对话不会生成；清除应用数据后重新选择这类目录也一样。真正需要判断的是目录里是否已有本应用的记录数据，而不是目录里是否有任何文件。

## What Changes

- 默认对话创建条件改为：目录中不存在本应用的记录文件（会话文件、设置文件、同步日志或旧版笔记文件）时，创建“极其重要”和“草稿”，并默认选中“草稿”。
- 目录中只有无关文件或空目录（例如遗留的空 `attachments` 文件夹）时，仍创建默认对话。
- 目录中已有本应用记录文件时 MUST NOT 创建默认对话，包括用户删除默认对话后重新打开、卸载重装后重新选择原目录。
- 移除“目录是否完全没有文件”的判断逻辑。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `default-conversations`: 首次安装默认对话的触发条件由“记录目录没有任何文件”改为“目录没有本应用的记录数据”。

## Impact

- `RecordRepository`：恢复记录时记录目录中是否存在本应用的记录文件，并对外提供该状态。
- `ChatRepository`：不再以目录文件数量决定是否创建默认对话。
- `ChatSessionService`：默认对话创建前的防御性判断与已删除对话保持一致。
- 单元测试与模拟器验证：覆盖含无关文件目录、含本应用数据目录、删除后重开等场景。
