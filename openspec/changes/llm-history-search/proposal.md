# Proposal

## Why

用户常在输入框里用自然语言回想旧内容（例如「之前说过的报销」「上次讨论的方案」），但当前只能手动翻会话列表逐条查找。应用已接入 OpenAI 兼容的 LLM，且已有发送后的逐条建议链路，却没有「查找历史消息」这一意图，用户的历史记录因此难以被快速找回。

## What Changes

- 在用户消息发送成功后的逐条建议分析中新增 `search` 意图：模型判断消息是否在请求查找历史消息，并给出 1–3 个检索关键词。
- 应用按关键词在本地跨全部对话检索消息标题与内容，按命中关键词数量与时间排序，最多返回 5 条；检索在设备本地完成，不把会话内容整体发给模型。
- 命中搜索意图时插入左侧建议气泡，文案为「搜索到如下消息：」，每条结果为可点击超链接，显示会话标题与消息摘要。
- 点击结果切换到对应对话，滚动定位并短暂闪烁该消息气泡；对话或消息已被删除时给出提示且不跳转。
- 没有检索到结果时，气泡显示「未找到相关消息」。
- 搜索结果气泡仍为内存态：不写入会话文件、快照、导出或局域网同步载荷，重启后消失；搜索请求消息本身照常保存。
- 错别字修正与提醒建议的既有行为不变，三类建议可在同一气泡内分段共存。

## Capabilities

### New Capabilities

- `history-message-search`: 基于 LLM 意图的历史消息搜索，包括意图识别、跨对话本地检索、结果气泡与跳转定位。

### Modified Capabilities

- 无。仅扩展已存在但尚未归档的逐条建议链路，不改变主 specs 中任何既有能力的契约。

## Impact

- AI：`MessageAssist` 增加 `search` 结果模型；`MessageAssistPrompt` 增加搜索意图字段与校验；`AiService.assist` 签名不变。
- 数据：新增只读的跨对话消息检索入口，不新增持久化结构，不改 `Snapshot.kt`、不改 Room 版本、不改 `LAN_SYNC_VERSION`。
- 界面：`ChatViewModel` 增加检索结果内存态与跳转动作，`ChatScreen` 的建议气泡增加可点击结果链接，`MainActivity` 传入新动作。
- 测试：搜索意图解析与校验、本地检索排序与上限、跳转定位、无命中与失败降级。
