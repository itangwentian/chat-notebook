# Design

## Context

`RecordRepository` 通过 SAF 维护按对话划分的 JSON 文件，并重建 Room 索引。`SessionFileCodec` 的代数仅对本机有意义，拆分时会过滤已删除对话。同步必须独立保存对话版本与删除记录，并补足应用中断后提交恢复所需的信息。附件引用当前存放相对路径，转发可以复用同一文件。不同设备上的相对路径不能作为附件内容标识。

发布版清单当前移除 `INTERNET`，现有隐私政策、用户协议和首次启动说明也承诺该版本无联网功能。启用局域网同步需要同步修改清单、发布说明和同意版本。

## Goals / Non-Goals

- 首版支持扫码配对的两台设备前台互通，笔记通过有身份校验的局域网连接直接复制。
- 采用对话级差异与内容寻址的附件差异，复用现有记录结构和校验链。
- 范围限于应用直接连接、单个配对关系和用户选择的记录目录。功能无需账号、云端存储或后台常驻。

## Decisions

### 设备配对与前台连接

- 使用 Android NSD 在可用局域网接口发布并发现同步服务。记录目录已授权、同步启用、应用处于前台时才注册和监听。配对前服务广告仅携带协议版本和短期发现标识。离开前台、暂停、设备解绑或网络切换时注销服务并关闭连接。限制连接落在当前局域网接口及实际可达的本地地址。
- 一端主动展示二维码，另一端主动扫描。二维码包含临时发现标识、随机的一次性令牌及展示端公钥的完整指纹。扫码端在初始 TLS 连接中校验该指纹，展示端验证令牌和扫码端的密钥持有，双方直接持久化信任。显示二维码时提示有效期及授权含义。二维码两分钟有效且可取消，设备信任无到期时间。新扫码握手使用独立版本，已配对设备继续使用原同步协议。本机身份私钥放入 Android Keystore，后续连接以双方已固定的公钥进行 TLS 双向认证。
- 应用回到前台、已配对设备重新出现或本机成功提交变更时，合并短间隔内的触发并发起双向交换。双方发现时以设备标识排序选定发起端，避免重复握手。连接内发出变更通知，失败按上限退避重试。设置页通过 Flow 显示等待对端、同步中、已同步、暂停或错误。
- 当前目标 SDK 35 使用 `INTERNET` 访问局域网，按支持系统处理 NSD 兼容分支。提升级别前复核本地网络运行时权限要求。二维码扫码优先使用在设备上工作的方式，用户只在进入扫码功能时授权摄像头。设置中新增带输入框的操作如果需要输入，应按项目约定自动聚焦和显示软键盘。

### 差异协议和版本

- 从 `SessionFilePayload` 明确定义同步字段投影。移除打开时间、已读标记、处理中请求、模型配置、凭据和其他本机状态。保留已保存的整理文档。AI 请求执行状态与中间结果保留在本机。内容摘要采用稳定序列化、固定排序及 SHA-256，对附件以内容摘要表示，不使用本机路径参与摘要。传输前双方协商协议版本，清单与负载设定大小上限并做结构验证。
- 每个对话维护按设备标识索引的版本向量。每次本地内容提交只推进本机分量，导入对端修订时保留其版本。同步清单按对话 ID 包含状态、版本向量和内容摘要，并用附件摘要标识缺失内容。对话摘要相同且版本不同可以合并向量，无需重传正文。摘要不同且版本有先后关系时，只交换后继内容。首轮包含双端各自已有的对话清单，仅一端存在的记录按新增处理。对话级传输复用分文件边界，单条消息更新时可能重传该对话的 JSON 投影。
- 删除对话时在同一逻辑提交中保存带版本的删除标记。标记保存在用户目录且首版持续保留，原对话文件移除和设备重启后仍可传播。批量消息软删除通过对话投影保留。目录缺失、读取错误或旧目录升级时的历史空缺均不生成删除标记。

### 冲突与附件

- 版本向量不可比较且内容不同时，按稳定修订标识排序选定主版，另一版生成带来源的独立冲突对话。删除和编辑并发时，主记录保留删除标记，编辑版生成副本。用原对话 ID 与排序后的双亲修订标识导出确定性的冲突 ID，并按副本 ID 重映射消息、编辑历史、内部引用及合并关系。主记录的已解决版本覆盖双亲向量，副本有自己的版本；同步重试不会复制同一冲突。时间戳只用于展示。
- 以 SHA-256 和长度标识附件，接收端只请求本地缺失或校验失败的内容。二进制流写入临时文件，经长度和摘要校验后映射到本机安全路径，保留原附件种类和元数据。接收端忽略远端文件名中的路径信息。对话或冲突副本尚需引用的附件纳入保护，完成记录提交后复用附件引用清理规则处理无人引用的文件。

### 持久化与重试

- 同步元数据按目录保存版本、删除标记、已解决冲突和恢复信息。设备信任绑定本机公钥身份并保存在应用私有空间。更换目录时关闭旧同步会话，独立初始化新目录的同步清单并保留设备信任。旧格式信任记录中的目录字段在升级时忽略。重装导致身份密钥丢失时需要重新扫码。
- 对每个对话变更或冲突处理组先暂存附件、记录变更与同步元数据，用可恢复的提交日志划出提交边界。持久化记录内容和版本后再发布 Room 更新并确认已接收。提交中断时按日志恢复或回滚，同一修订重复提交不再追加。接收前以当前本机版本复核结果，有新编辑时重新比较，避免下载期间覆盖新写入的本地内容。后台或断线中止未提交的传输，启动恢复只处理本机文件。
- 保持原始正文不可变约束和现有快照校验，接收时验证对象所有权、内部引用和附件完整性。目录权限失效、空间不足或校验错误时返回可重试状态，已提交的其他对话仍然有效。

## Risks / Trade-offs

- [访客 Wi-Fi、AP 隔离和部分热点可能屏蔽设备互通或 mDNS] → 以可发现且可直连为同步条件，设置页提示检查网络和对端应用状态。
- [长对话中的小改动仍需传输该对话的同步投影] → 通过清单跳过未变化对话，并按附件内容去重。集成测试记录实际交换的对话数和附件字节数。
- [删除标记持续保留会增长] → 仅保留传播所需的标识和版本。首版测试覆盖长期离线后重连与重试去重。

## Migration Plan

1. 启用同步时从现有已校验快照生成初始清单，保存稳定 ID，首次配对按照新增和内容相同的规则合并。
2. 随功能发布更新发布版合并清单、隐私政策、用户协议、首次启动说明和同意版本。检查 Release 中远程 AI 仍处于关闭状态。
3. 暂停或关闭功能后，本机仍使用原有对话 JSON 和附件。回退安装前先关闭同步并保留记录目录，重装后须重新配对。
