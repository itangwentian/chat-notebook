# Proposal

## Why

同一对话在两台设备上并发编辑时，当前同步会把其中一侧另存为「同步冲突 · 设备…」副本，用户会看到两个对话，需要自己比对、搬运内容。用户希望冲突直接取并集，合并成一个对话。

## What Changes

- 并发冲突不再产生副本对话，而是把两端内容按并集合并回原对话，保持原对话 id 不变。
- 消息按 id 取并集；同一消息 id 两端内容不同时取 `updatedAt` 较新者（删除墓碑带时间戳，因此较新的删除仍生效）。
- 编辑历史、引用、表情、消息合并关系、整理文档按各自唯一键取并集；同键冲突时取会话更新时间较新一侧，仍相同则用内容摘要作确定性兜底。
- 标题取会话更新时间较新一侧；对话 `createdAt` 取较早、`updatedAt` 取较晚。
- 一端删除、另一端并发编辑时保持现有行为：删除生效，被编辑内容另存为副本，避免内容丢失。
- 合并结果必须对称、确定：两端各自计算得到同一份内容与同一份清单版本（逐设备最大值）。

## Impact

- 影响 `SyncConflicts.kt`（冲突解决改为并集合并）、`LanSyncProtocol`（只应用一个合并结果）及相关单测。
- 不改变 `LAN_SYNC_VERSION` 与记录文件格式；未升级的旧版本仍按原副本方式处理冲突。
- 冲突解决后对话中会出现两端各自新增的消息，按 `createdAt` 排序显示。
